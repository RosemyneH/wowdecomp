Writing WASM Addons (ABI v1)

Markdown copy for GitHub: Addons/Wasm/README.md.

Build

rustup target add wasm32-unknown-unknown
cargo build --target wasm32-unknown-unknown --release

Use the SDK in sdk/wow-addon-sdk (see examples/hello-world, inventory-watcher, ui-demo, unit-frames, whisper-window), or any language that can emit wasm32-unknown-unknown — a C example using raw imports is in examples/c-hello. Your module must export memory and wow_on_load() -> i32; export wow_on_event(ptr, len), wow_alloc/wow_free (provided by the SDK) to receive events. Importing anything outside module wow (including WASI) fails validation.

Package

MyAddon/
├── addon.toml     # [addon] id/name/version/api_version="1", [permissions], [limits]
├── addon.wasm
└── LICENSE        # optional; addon.sig is detected but not yet verified

Install by copying the folder into Interface/WasmAddOns/ in the client directory. Manifest limits are requests, clamped to host maximums. Sensitive permissions (chat.send, auction.*, storage.*, …) stay denied until the user grants them — grants persist per addon id + module hash in wasm-permissions.cfg.

Frames

ui_spawn(parent, kind) creates a frame, fontstring, texture, statusbar, or button. Parent 0 is UIParent; other parents must be a frame, button, or status bar you own. ui_style(handle, op, blob) places and colors it. The SDK's ui module builds the blobs: size, point, color, backdrop, show, status-bar value, justify, font size, frame level, strata. ui_set_text still sets font-string text and keeps newline characters. ui_create remains the older one-shot label. An addon that exports wow_on_update is called about five times a second.

examples/unit-frames draws player, target, and party panels. examples/whisper-window lists whispers. Both are original layouts. Health numbers need units.read and whisper text needs chat.read; until granted, the panels still show and the payloads stay redacted. From the developer console: wasmgrant example.unit-frames units.read and wasmgrant example.whisper-window chat.read.

Lua-shaped ports

docs/lua-wasm.html is the authoring guide. The play client keeps the original ElvUI and Details trees in their own Interface/WasmAddOns/<Name> folders. /ec opens ElvUI’s options. /details is the meter. port.wim opens per-person whisper windows, keeps history, and sends on enter. They are clean-room layouts for this client and install like the other wasm packages. The Lua calls they use are ui_bind / WASM_UI, ui_get_text, unit_names, and edit boxes. From the developer console:

wasmgrant port.wim chat.read
wasmgrant port.wim chat.send
wasmgrant port.wim storage.read
wasmgrant port.wim storage.write

Inspect & debug

In game: /script DEFAULT_CHAT_FRAME:AddMessage(WasmAddonInspectorText()) shows state, hash, granted/denied permissions, imports, memory/fuel/host-call counters and the activity log. Headless: wasm_addon_host <addon-dir> --inspector. Host functions return negative error codes (-2 permission, -3 bad memory, -4 stale handle, -6 limit, -7 buffer too small) instead of trapping your addon; traps and fuel exhaustion suspend/fault only your addon. Full status: docs/wasm-addon-progress.md.

Versioning

api_version = "1" in the manifest is checked against the host ABI. Breaking ABI changes bump the version; addons built for older versions are rejected with a clear load error rather than misbehaving.
