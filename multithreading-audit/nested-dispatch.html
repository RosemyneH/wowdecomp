Nested job dispatch investigation

Confirmed API-level deadlock

A callback executing within an active job cannot call Job::Wait() successfully: RunRanges decrements remaining only after the callback returns, whereas Join waits for remaining == 0. A nested nonempty Start or ParallelFor also calls Wait before publishing, so it has the same circular dependency. A worker executing the callback additionally cannot increment its finished acknowledgement until the callback returns. See Engine/Source/Base/Job/JobSystem.cpp, functions RunRanges, WorkerMain, Join, Wait, Start and ParallelFor.

On Linux, nested_job_repro.cpp initializes the pool and invokes a one-range parallel job whose callback calls Wait, nonempty Start, or nonempty ParallelFor. Build with c++ -std=c++17 -O2 -pthread -I. multithreading-audit/nested_job_repro.cpp Engine/Source/Base/Job/JobSystem.cpp -o /tmp/wow-nested-repro from the repository root. Each of timeout 3s /tmp/wow-nested-repro wait, timeout 3s /tmp/wow-nested-repro start, and timeout 3s /tmp/wow-nested-repro parallel timed out (exit 124). This intentionally hangs on the current implementation; do not run without a timeout. It establishes API-level reachability, not a production trigger. A source search finds the explicit job call sites in M2Scene.cpp, CM2SceneRender.cpp and World.cpp; their full callback call graphs have not yet been checked for indirect nested dispatch.

The frustum Cull and mathematical helpers still require transitive inspection, and this static trace is not runtime verification; nested dispatch through uninspected callees remains a HYPOTHESIS.

The sphere-frustum path constructs a CAaSphere whose constructor only initializes its radius (Engine/Source/Tempest/CAaSphere.cpp:7-9), then runs a six-plane arithmetic loop without further calls (Engine/Source/Tempest/CFrustum.cpp:68-80). On this inspected callback path there is no identified nested job call. This does not establish that the shared frustum, projection matrices, clip buffer, and doodad inputs remain immutable during execution or that external library behavior was runtime-tested; inspect concurrent writers and ownership separately.

Next steps

Trace each callback's transitive calls before asserting game reachability. Decide and document whether nesting is unsupported or should execute inline; any change must consider callback ordering, exception behavior and lifecycle concurrency. Add a bounded regression for the chosen contract without allowing a hung test process to stall the suite.
