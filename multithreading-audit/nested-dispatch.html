Nested job dispatch investigation

Confirmed API-level deadlock

A callback executing within an active job cannot call Job::Wait() successfully: RunRanges decrements remaining only after the callback returns, whereas Join waits for remaining == 0. A nested nonempty Start or ParallelFor also calls Wait before publishing, so it has the same circular dependency. A worker executing the callback additionally cannot increment its finished acknowledgement until the callback returns. See Engine/Source/Base/Job/JobSystem.cpp, functions RunRanges, WorkerMain, Join, Wait, Start and ParallelFor.

On Linux, nested_job_repro.cpp initializes the pool and invokes a one-range parallel job whose callback calls Wait, nonempty Start, or nonempty ParallelFor. Build with c++ -std=c++17 -O2 -pthread -I. multithreading-audit/nested_job_repro.cpp Engine/Source/Base/Job/JobSystem.cpp -o /tmp/wow-nested-repro from the repository root. Each of timeout 3s /tmp/wow-nested-repro wait, timeout 3s /tmp/wow-nested-repro start, and timeout 3s /tmp/wow-nested-repro parallel timed out (exit 124). This intentionally hangs on the current implementation; do not run without a timeout. It establishes API-level reachability, not a production trigger. A source search finds the explicit job call sites in M2Scene.cpp, CM2SceneRender.cpp and World.cpp; their full callback call graphs have not yet been checked for indirect nested dispatch.

Callback trace: doodad culling

WoW/Source/WorldClient/World.cpp:4196-4201 dispatches CullDoodadRange at 32 or more entries; smaller batches call it directly. The callback at World.cpp:4135-4147 calls the sphere overloads of CWorldScene::FrustumCull and CWorldOcclusion::QueryBuffer, and writes its own result slots. FrustumCull at World.cpp:2174-2179 constructs a sphere and calls the frustum's Cull; the sphere QueryBuffer at CWorldOcclusion.cpp:487-527 performs projection, clipping and buffer reads without a direct job call. These inspected functions do not directly dispatch or wait. The frustum Cull and mathematical helpers still require transitive inspection, and this static trace is not runtime verification; nested dispatch through uninspected callees remains a HYPOTHESIS.

The sphere-frustum path constructs a CAaSphere whose constructor only initializes its radius (Engine/Source/Tempest/CAaSphere.cpp:7-9), then runs a six-plane arithmetic loop without further calls (Engine/Source/Tempest/CFrustum.cpp:68-80). The sphere occlusion path uses the vector-matrix multiplication at Engine/Source/Tempest/C44Matrix.cpp:309-315 and CMath::fint_ at Engine/Source/Tempest/CMath.h:75-77; these perform arithmetic and lrintf, respectively, with no in-tree job dispatch. On this inspected callback path there is no identified nested job call. This does not establish that the shared frustum, projection matrices, clip buffer, and doodad inputs remain immutable during execution or that external library behavior was runtime-tested; inspect concurrent writers and ownership separately.

Callback trace: doodad skin fill

Engine/Source/Model2/CM2SceneRender.cpp:980-1016 locks a vertex buffer on the caller, dispatches FillDoodadSkin for at least eight instances, then unlocks after the synchronous barrier. The callback at lines 620-630 uses a distinct n * stride destination for each instance and calls M2SkinTake or a transform function. M2SkinTake and SkinLookupJob (M2Scene.cpp:1786-1805,1997-2011) read the lookup and copy cached bytes; their inspected bodies contain no job dispatch. The C++, SSE and AVX2 transform implementations (M2Model.cpp:3803-3961, M2SkinAvx2.cpp:20-97,110-157) perform local arithmetic and destination writes, with no direct job calls in those implementations. This is static inspection, not proof of input lifetime or graphics-backend mapped-buffer thread safety. HYPOTHESIS: concurrent mutation of the skin cache or model inputs could race these reads; inspect ordering and backend mapping contracts and test before concluding safety. The selected transform function depends on initialization and platform configuration.

The public header explicitly prohibits callbacks from calling Job:: (Engine/Source/Base/Job/JobSystem.h:16-24), so the nested reproducer demonstrates a prohibited-use deadlock rather than an established violation of the documented API contract. Production reachability still depends on whether a callback transitively violates that restriction.

Callback trace: asynchronous skin preparation

WoW/Source/WorldClient/CWorldSceneRender.cpp:186-200 calls M2SkinPrepare after animation and before terrain rendering. Engine/Source/Model2/M2Scene.cpp:1922-1985 waits for previous work before clearing the job vector, assigns each accepted job an aligned offset after the preceding allocation, resizes the byte vector, then publishes SkinRange. The callback at lines 1855-1883 writes each assigned byte region through WriteSkin, which selects the previously inspected transform functions; neither wrapper directly calls Job::. Assuming the vertex-count arithmetic and model inputs remain valid, jobs have separate output regions. This is static inspection, not proof against malformed asset arithmetic or concurrent mutation of model and skin data.

CM2Scene::Draw calls M2SkinFinish before drawing (M2Scene.cpp:1992-1994,2602-2619), and finish waits before publishing readiness. Both CM2Model::SetVertices and FillDoodadSkin attempt cache reads through M2SkinTake (M2Model.cpp:3399, CM2SceneRender.cpp:620-630); an early read while not ready falls back to skinning, but the flag and cache are not independently synchronized for arbitrary concurrent callers. HYPOTHESIS: model inputs could be modified or destroyed by intervening render/update work while skin jobs run. Trace the intervening calls and model lifetime, including alternate draw entry points, before concluding safety. Validate with a controlled overlap test or thread sanitizer where practical; do not move the barrier without that evidence.

Callback trace: model animation

CM2Scene::Animate builds root models and synchronously dispatches AnimateModelRange, which selects AnimateMTSimple or AnimateMT (Engine/Source/Model2/M2Scene.cpp:228-248,2083-2110). The inspected bodies of both variants and AnimateAttachmentsMT contain no direct Job:: calls; attachments recursively invoke either animation variant (Engine/Source/Model2/M2Model.cpp:5457-5647,5812-6467). Both variants call animation track specializations and texture-transform helpers; the full variant also calls particle animation and spline-track specializations. AnimateParticlesMT calls HasLiveParticles as well as track helpers, while AnimateTextureTransformsMT invokes track and matrix helpers (M2Model.cpp:5136-5261). No direct job call occurs in those two inspected helper bodies. This is a partial static trace, not a proof that all transitive callees respect the callback contract or that model ownership is race-free. Inspect track specializations, emitter and math helpers and their callees before closing this path; nested dispatch through them remains a HYPOTHESIS.

The particle branch calls CParticleEmitter2::HasLiveParticles only when m_emitting is false (M2Model.cpp:5148-5150). Its body checks the live-list count and recursively visits child emitters, with no direct job call (Engine/Source/Services/ParticleSystem2.cpp:1393-1407). The same emitter's StepUpdate modifies that list (ParticleSystem2.cpp:2018-2083); the animation loop runs its AnimateST pass after the synchronous parallel barrier (M2Scene.cpp:2108-2117). This ordering alone does not rule out another writer or shared emitter ownership. HYPOTHESIS: an overlapping emitter update or destruction could race the worker's list and child reads; trace ownership and all update entry points and validate with a controlled overlap or ThreadSanitizer before concluding safety. The recursive search's termination also depends on a valid emitter tree.

The inspected model update path is more specific: AnimateST calls AnimateParticleST (M2Model.cpp:3231,3245), which calls emitter Update (M2Model.cpp:6474,6583); Update reaches InternalUpdate and StepUpdate (ParticleSystem2.cpp:1042-1068,2463-2535). The scene's barrier therefore orders this ordinary update after the parallel liveness query. Particle models are subsequently animated within that serial path (M2Model.cpp:6585-6591). This does not establish exclusive emitter ownership or rule out other updates; Count reads the ordinary non-atomic array count (Engine/Source/Storm/H/stpl.h:91-96,660-662). No runtime concurrency test was performed.

Next steps

Trace each callback's transitive calls before asserting game reachability. Decide and document whether nesting is unsupported or should execute inline; any change must consider callback ordering, exception behavior and lifecycle concurrency. Add a bounded regression for the chosen contract without allowing a hung test process to stall the suite.
