Benchmark record

Initial synthetic chunk experiment

Linux x86_64, AMD Ryzen 5 5600H, 12 logical CPUs, GCC 16.2.1; the existing pool selected 10 workers. Build and run: c++ -std=c++17 -O2 -pthread -I. multithreading-audit/job_benchmark.cpp Engine/Source/Base/Job/JobSystem.cpp -o /tmp/wow-job-bench && /tmp/wow-job-bench.

The benchmark calls the actual internal Publish followed by Wait, selecting 10, 20, 40 and 80 chunks over 4096 items. It is not the public ParallelFor path: Wait takes an extra mutex and the normal ParallelFor uses 11 chunks on this host. Each callback computes independent deterministic integer chains; a serial reference is checked after warmup and each sample. Uniform uses 200 steps per item, uneven uses 50–650 periodically, and skewed assigns 8000 steps to the first 1/32 of items and 50 to the rest. Each sample is the elapsed time for 20 batches divided by 20, five samples in fixed order per configuration. An initial run overlapped a build/test; results below are from a subsequent run without those commands running. CPU frequency, background activity and order effects were not controlled.

Variability is substantial; these data do not justify a scheduler change or a performance claim. That initial run did not measure other worker counts, the current 11-chunk ParallelFor baseline, empty/small workloads, representative game workloads, frame times, or other platforms. Randomized order, isolation and more repetitions are needed. The previous lifecycle test is a correctness test, not a benchmark.

Public ParallelFor baseline and contemporaneous chunk experiment

On the same Linux host and with the same compiler command above, the revised benchmark also measures the actual public ParallelFor path, which selects 11 chunks for 10 workers. Publish/Wait is still a different API path, so these measurements are not an isolated comparison of chunk counts. Each row contains five milliseconds-per-batch samples; the serial reference was checked after warmup and every sample. Runs are fixed-order, without CPU isolation or frequency control. The much lower timings than the earlier run demonstrate that the two runs are not a controlled before/after comparison.
